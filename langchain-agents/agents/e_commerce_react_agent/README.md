# E-commerce ReAct Agent

This example implements a small e-commerce assistant that uses the **ReAct (Reason + Act)** pattern. Instead of answering a pricing request from memory, the language model reads a prompt that describes the available tools, chooses an action, receives the tool result as an observation, and continues until it produces a final answer.

The agent is intended as a learning example: it demonstrates a prompt-driven tool loop and a simple in-memory product catalog. It is not connected to a store, inventory system, payment provider, or production pricing service.

## What it can do

- Look up the listed price of a product.
- Apply a supported discount tier to a price returned by the lookup tool.
- Explain the discounted result in a final response.
- Emit LangSmith traceable runs for the agent and tool calls when LangSmith tracing is configured.

The prompt instructs the model to look up a product price before applying a discount, to use the discount tool rather than calculate the discount itself, and to ask the user for a tier when none is specified.

## How the ReAct loop works

1. `ECommerceReACTAgent.run()` reads the prompt from `prompts/ReAct_prompt.txt`.
2. It inserts the current tool descriptions, tool names, and user question into the prompt.
3. The prompt and accumulated scratchpad are sent to the configured Ollama chat model.
4. If the response contains `Final Answer:`, the agent returns the text following it.
5. Otherwise, it parses `Action:` and `Action Input:`, invokes the selected tool, and appends the model response and tool result as an `Observation:` to the scratchpad.
6. The loop continues until a final answer is received or the iteration limit is reached.

This implementation uses a text-formatted action protocol rather than LangChain's native tool-calling interface. The model response therefore needs to follow the prompt's `Thought` / `Action` / `Action Input` / `Observation` format.

## Available tools and sample data

The tools are defined in `tools/agent_tools.py` and use in-memory dictionaries:

| Tool                                   | Purpose                                                                      | Current behavior                                                                              |
| -------------------------------------- | ---------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `get_product_price(product_name)`      | Looks up a product's listed price.                                           | `laptop`: $1,200.00; `mouse`: $10.00; `keyboard`: $20.00. Unknown product names return `0.0`. |
| `apply_discount(price, discount_tier)` | Applies the selected percentage and rounds the result to two decimal places. | `silver`: 10%; `gold`: 15%; `platinum`: 20%. An unknown tier currently applies a 0% discount. |

Names are looked up as dictionary keys, so use the lowercase product and tier names shown above. Update these dictionaries to change the demonstration catalog; they are not loaded from an external source.

## Requirements

- Python 3.11 or newer.
- [Ollama](https://ollama.com/) installed and running locally.
- The model configured by default in `agents/e_commerce_agent/constants.py` (currently `qwen3.5:4b`) downloaded in Ollama.
- The Python dependencies declared by the `langchain-agents/pyproject.toml` project.

## Run it

From the `langchain-agents` directory, install the project dependencies and download the configured model:

```powershell
uv sync
ollama pull qwen3.5:4b
```

Make sure the Ollama service is running, then launch the agent in module mode from that same directory:

```powershell
uv run python -m agents.e_commerce_react_agent.main
```

The example in `main.py` asks the agent to apply the silver discount to a laptop. With the sample catalog, the expected discounted price is **$1,080.00**; the exact wording of the final response is generated by the model.

Module mode matters because the application imports the `agents` and `shared` packages from the project root. Running the file directly from an unrelated working directory may fail to resolve those imports.

## Configuration

The entry point obtains its defaults from `agents/e_commerce_agent/constants.py`:

| Setting          | Current default | Description                                                                                                                                               |
| ---------------- | --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DEFAULT_MODEL`  | `qwen3.5:4b`    | Ollama model name passed to the chat API.                                                                                                                 |
| `TEMPERATURE`    | `0.8`           | Passed to the agent constructor. The current request options in `agent.py` set `temperature` to `0`, so that value is what the model call currently uses. |
| `MODEL_PROVIDER` | `OLLAMA`        | Passed to the agent constructor; the current implementation calls Ollama directly.                                                                        |
| `MAX_ITERATIONS` | `10`            | Iteration bound. The loop currently uses an exclusive upper bound, so it performs at most 9 passes for this setting.                                      |

Change the values in that constants module to adjust the defaults. The `main.py` example currently loads `OPENAI_API_KEY`, but the value is not used by this Ollama-backed implementation; a provider API key is not required to run it locally.

## Optional LangSmith tracing

The agent and tools are decorated with `langsmith.traceable`. To send traces to LangSmith, configure the LangSmith environment variables used by your account, including `LANGSMITH_API_KEY` and `LANGSMITH_TRACING=true`, before launching the application. Keep credentials in a local `.env` file or environment variables, and never commit secrets to GitHub. Tracing is optional for the basic local run.

## Current limitations

- The catalog and discounts are hard-coded sample data; there is no live inventory, currency, tax, shipping, or checkout integration.
- An unknown product returns `0.0`, and an unknown discount tier results in no discount. These are demonstration defaults, not validation suitable for a real shop.
- The action parser expects `Action:` and `Action Input:` lines and simple comma-separated arguments. Malformed model output or tool input outside that format may not be handled gracefully.
- If the model does not provide a parseable final answer within the loop bound, `run()` returns `None`.
- The configured `temperature` constructor value is currently superseded by the fixed `temperature: 0` option on the Ollama request.

## Project files
